# Task: VLA / robotics latency budget planner (Rust → WebAssembly)

Build an original, small, public static web app named **Latency Budget**. Write original code and assets only. The app helps robotics and VLA developers answer: “Can this perception → policy → actuation pipeline meet its control-loop deadline, and which stage is the bottleneck?”

## Product scope
One core feature plus two small extras; target roughly 400–800 lines of Rust and 4–8 unit tests.

### Core feature: editable pipeline budget
- Single-page Korean-first UI with an English toggle.
- Six synthetic default stages: Sensor capture, Decode, Perception, Policy, Safety filter, Actuation.
- Each stage has editable name, typical latency (ms), p95 latency (ms), and parallel worker count (1–8). Rows can be added, removed, and reordered.
- Inputs: target loop rate (Hz) and deadline (ms). Enforce finite non-negative values and p95 >= typical.
- Compute and show:
  - sequential typical and p95 end-to-end latency (sum of stages);
  - pipelined steady-state throughput from the slowest effective stage `typical / workers`, expressed as max Hz;
  - deadline margin for typical and p95, pass/warn/fail status;
  - bottleneck stage and its share of sequential latency.
- A large responsive timeline/waterfall visualization is the hero: proportional colored blocks for stages, typical vs p95 overlays, deadline marker, bottleneck highlight, hover/focus tooltip, and a compact HUD for total latency, throughput, margin, and status. Use Canvas 2D or SVG generated by the app; no chart library.
- Explain clearly that this is a deterministic planning estimate, not a profiler; correlated jitter, queueing, scheduling, transfer overlap, and hardware contention require measurement.

### Small extras
1. Three synthetic presets: Vision control, Local VLA policy, Remote-assisted policy. Label them illustrative and editable; no vendor/product claims.
2. Export the current budget as a local CSV download. No import, sharing, accounts, or storage.

### Polished UI
- Dark design tokens, system fonts, subtle grid/gradient background, full-width timeline hero, slim toolbar, compact collapsible settings cards, colored stage chips, 150–200 ms transitions, mobile bottom-sheet layout, helpful first-run hint.
- Keyboard-accessible controls, visible focus states, reduced-motion support, semantic labels.
- The initial example must be useful immediately. No 3D is needed because this tool visualizes time, not spatial geometry.

## Architecture and tests
- Workspace with `crates/lb_core` (pure Rust) and `crates/lb_web` (wasm-bindgen/web-sys).
- Core types and functions should be deterministic and host-testable.
- Include 4–8 hand-checkable tests covering sums, p95 validation/normalization, throughput with workers, bottleneck selection, deadline status boundaries, and CSV escaping.
- No dependencies beyond wasm-bindgen, web-sys, and js-sys in the web crate.
